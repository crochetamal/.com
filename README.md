# Crochet.Amal: متجر كروشيه (GitHub Pages)

موقع ثابت (HTML + CSS + JavaScript) بدون خادم أو قاعدة بيانات. الطلبات تتم عبر واتساب: https://wa.me/212700278798

## الملفات
- `index.html`, `css/style.css`, `js/app.js`: الموقع ولوحة التحكم
- `data/products.json`: كتالوج المنتجات الأصلي (عدّليه بدون لمس الكود)
- `data/site.json`: نصوص الصفحة، الأقسام، الآراء، روابط التواصل، رقم واتساب
- `assets/images/`: الصور

## النشر على GitHub Pages
1. أنشئي حسابًا على github.com ثم مستودعًا جديدًا (مثلًا `crochet-amal`) بوضع Public.
2. اضغطي **Add file > Upload files** وارفعي **محتويات** المجلد (index.html و css و js و data و assets) ثم **Commit changes**.
3. من **Settings > Pages**: اختاري Source = **Deploy from a branch**، Branch = `main`، المجلد `/ (root)`، ثم **Save**.
4. بعد دقيقة يظهر الموقع على `https://USERNAME.github.io/crochet-amal/`. كل المسارات نسبية فتعمل تحت هذا الرابط.

## لوحة التحكم
افتحي صفحة المشرفة المنفصلة: `https://crochetamal.github.io/.com/admin.html` (لا يوجد أي زر لها في المتجر، احفظي الرابط) ثم أدخلي كلمة المرور المتفق عليها. 
من اللوحة: إضافة منتج، تعديل الاسم والوصف والثمن (بالدرهم) ورابط الصورة (مع معاينة)، حذف، ترتيب (▲▼)، إخفاء/إظهار، معاينة، ونشر.

## البيانات والنشر السحابي
يستخدم التطبيق مشروع Firebase المحدد في `js/firebase-config.js`، وFirestore لحفظ المنتجات والصور المصغّرة وإعدادات الواجهة. الحفظ المحلي مسودة احتياطية، وليس دليلاً على النشر. يجب تسجيل الدخول بحساب الإدارة الموثق وانتظار رسالة نجاح النشر السحابي. يمكن تصدير المسودة من اللوحة.

## النسخ الاحتياطي والاستعادة
- **تصدير JSON** = نسخة احتياطية. **استيراد JSON** = استعادتها (تدخل المسودة ثم انشريها).

## تجربة محلية
افتحي الطرفية في المجلد وشغّلي `python3 -m http.server 8000` ثم زوري http://localhost:8000 (فتح الملف مباشرة لا يعمل بسبب `fetch`).

## ملاحظة
رابط إنستغرام في `data/site.json` ضمن `social`. لإضافة فيسبوك أو تيك توك أضيفي `"facebook"` أو `"tiktok"` مع الرابط الصحيح.

## إعداد Firebase والتحقق قبل النشر

- الموقع ولوحة الإدارة يستخدمان المشروع `amale-crochet` ونفس إعدادات Firebase. المنتجات في `products/{id}` وإعدادات الواجهة في `products/__site_meta__` (الحقل `hero`). الصور المرفوعة مضغوطة ومضمنة داخل المستندات، ولا يستخدم التطبيق Firebase Storage.
- فعّلي Email/Password في Authentication، وتحققي من أن بريد `crochetamal64@gmail.com` موثّق، وأن نطاق الموقع مصرح به ضمن Authorized domains.
- **قبل تغيير القواعد:** راجعي القواعد المنشورة في Firebase Console > Firestore Database > Rules. قارنيها مع `firestore.rules` ومع أي مسارات أخرى يحتاجها مشروعك. إذا كانت سليمة احتفظي بها؛ وإلا عدليها بعد المراجعة ثم Publish. الملف في المستودع لا ينشر القواعد تلقائياً. القواعد المحلية تقصر الكتابة على البريد الإداري الموثق، وتسمح بالقراءة العامة للمسارين الموجودين في الملف.
- بعد دمج التعديلات ونشر ملفات الموقع على GitHub Pages، اختبري بحساب الإدارة وبجلسة زائر منفصلة. لا تُعد رسالة الحفظ المحلي نجاحاً سحابياً.
- عند ظهور تعارض، صدّري المسودة أولاً من لوحة الإدارة. افتحي اللوحة في متصفح أو ملف مستخدم جديد لمراجعة النسخة السحابية، ثم أعيدي تطبيق التعديلات المطلوبة عليها وانشريها. لا تمسحي بيانات المتصفح لحل التعارض. مسودات قديمة لم تحفظ نسخة مرجعية سحابية تتطلب هذه المراجعة أيضاً.
- إذا كانت الصورة أو مجموعة التغييرات كبيرة، قللي الصور أو قسمي التعديلات وانشري مجدداً. لا تُحذف الصور تلقائياً لتجاوز حد Firestore. النشر الذري يرفض أكثر من 450 عملية أو طلباً تقديرياً يتجاوز 8 ميغابايت.
- للاختبار المحلي: `node tests/sync.test.cjs`. هذا اختبار بمحاكاة Firestore، وليس بديلاً عن اختبار القواعد على Firebase Emulator أو التحقق من النشر الفعلي.
